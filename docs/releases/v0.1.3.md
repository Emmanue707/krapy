Fixes the crash right after scanning, found on a Realme/ColorOS phone.

- the app no longer crashes when mirroring starts. It re-created the screen capture display, which Android 14 forbids (one display per capture session); it now creates it once and only resizes it
- the phone now sends the Start message the desktop waits for, so the session actually begins instead of sitting at "waiting for the phone"
- connecting and control messages run off the main thread, so no more false "can't reach" toast on the first try
- every step after the scan shows an error instead of crashing, and the encoder falls back to 720p if the phone's encoder refuses the size
- if krapy ever crashes, the next launch shows the error with a Copy button so you can send it

Desktop builds are unchanged from 0.1.2 apart from the version number.

### Assets

- `krapy-0.1.3.apk` signed phone app (Android 10+). Installs over 0.1.2.
- `krapy-0.1.3-linux-x86_64.tar.gz`, `-windows-x86_64.zip`, `-macos-aarch64.tar.gz` (macOS build is unsigned)
- `SHA256SUMS`
